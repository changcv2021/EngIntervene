# Anonymous attachment screening

## Public repository notice

The source-code attachment was screened independently of the hosting account.
A public repository exposes its owner and new commit metadata; hosting this
code on an identifiable account does not provide an anonymous review URL.
Publication keeps the contributor name neutral and excludes original experiment
history, personal email addresses and infrastructure paths.

The final package was checked for disclosed author/account identifiers, institution and cluster names, institution-specific paths/endpoints, email addresses and common credential formats. No matching values were found. The private deny rules are deliberately not bundled because those rules themselves contain identity information.

No repository history, symbolic links, hidden credential files, logs, model weights, answers, images or document metadata are included. Archive members use neutral relative paths, fixed timestamps and neutral permissions; no local owner/group IDs are stored. Hash manifests expose checksums, not original host paths. Third-party model/library identifiers are retained.

This is screening against disclosed identifiers and generic credential patterns, not a guarantee against unknown aliases. Run another review if you edit configuration, add outputs or initialize/push a repository. Do not upload private validation work directories. The archive was re-opened and every member checked against its audited source bytes.
